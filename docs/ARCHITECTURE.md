# Architecture

SyncPilot has an offline protocol layer and a pilot-owned application layer.

The contract describes the project, source scope, canonical repository, transport and destination. Contract v5 binds participant projects rather than permanent conversations. Actors are qualified per operation.

The document engine builds an exact Git package. Desktop Commander transports it; a configured secondary provider may be used only after the protocol establishes primary unavailability and conclusive non-delivery. Uncertain reception requires collection, not a new deposit.

The decision adapter tracks validated human decisions and conflicts without applying them automatically to Git. Persistence tracks durable destination access separately from transport; an accessible folder is not automatically a native project source.

The mission entry point prepares a technical mission, observes qualified receiver availability, dispatches through the supported Codex application-server protocol, collects terminal results and confirms independently. Receiver creation authority belongs outside the received package. An idle chat does not prove absence of a native writer.

The source helper issues a request-bound marker and validates bounded native inventory/readbacks supplied by an authenticated external pilot. It emits the existing five-field actor record. It does not discover chats, call an API, send a message or grant authority itself.

Authentication, tool availability, project qualification and the human mandate remain the pilot's responsibilities. The bridge uses the caller's installed CLI and normal host authentication; this repository supplies neither credentials nor live connection bindings.
